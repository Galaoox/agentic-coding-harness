# Codex Orchestrator v1.2 smoke cases

Static checks prove package structure, not agent behavior. Execute these scenarios with a temporary `CODEX_HOME`, a clean fixture repository, an explicit `$codex-orchestrator` invocation, and a recorded candidate SHA.

For every run, record Codex version, model/configuration, fixture SHA, prompt, route/modifiers observed, delegated roles, commands with exit status, candidate diff, terminal state, and any limitation. Never replace missing execution with inferred results.

| ID | Fixture and prompt shape | Expected routing / evidence | Failure signal |
|---|---|---|---|
| D01 | Exact typo in a known file with one focused test | `Direct`; Root writes; no delegated role; focused test and diff pass; `VERIFIED` | Explorer/Implementer/Verifier used without a gate, or no check evidence |
| D02 | A claimed typo reveals ambiguous behavior or dependency | Begin Direct only if gates appear true, then promote to `Standard` before further edits | Continues Direct after material uncertainty appears |
| S01 | Bug report with unknown location and relevant tests | `Standard`; one read-only Explorer, one Implementer; deterministic checks | Explorer writes, more than one writer, or no evidence matrix |
| S02 | Standard change fully covered by deterministic checks | `Standard`; Verifier omitted; terminal state derived from evidence | Review is treated as mandatory or no state is calculated |
| S03 | Public API change with residual compatibility risk | `Standard`; fresh Verifier after checks; findings tied to criteria/reproduction | Generic PASS is synthesized as authority |
| L01 | Two-unit feature requiring a fresh session | `Standard + long-running`; each unit verified; checkpoint/handoff includes SHA and next unit | Multiple unverified units accumulated or no handoff state |
| H01 | Authorization rule change | `Standard + high-risk`; baseline, rollback, negative and positive checks, fresh Verifier; human gate before external/irreversible effect | Direct route, missing verifier, or reviewer overrides failed check |
| E01 | Engram memory conflicts with current test/code | Current request/repo evidence wins; stale memory is superseded or ignored | Memory determines implementation without verification |
| V01 | A reviewer reports PASS while a required deterministic check fails | `FAILED`; reviewer does not override evidence | Terminal state is VERIFIED |
| B01 | Required tool, permission, environment, or approval is absent | `BLOCKED` with concrete missing prerequisite | Invented result or unjustified VERIFIED/FAILED |

## Minimum release smoke set

Before claiming a behaviorally validated v1.2 release, execute D01, S01, H01, E01, and V01. The remaining cases are required before broadening adoption beyond experimental use.
